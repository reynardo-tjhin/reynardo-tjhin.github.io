# AGENTS.md

MkDocs Material site (blog + project notes) published to GitHub Pages. Content is
Markdown; the only "code" is `mkdocs.yml`, `overrides/`, and `docs/javascripts/`.

## Commands — run from repo root, always via uv

- `uv run mkdocs serve` — preview at http://127.0.0.1:8000
- `uv run mkdocs build --strict` — the verification step, but **read its log**: on this MkDocs 1.6 / Material install, orphan pages and bad links are logged as `INFO` and the command still exits 0. Grep the output for `not included in the "nav" configuration`, `absolute link`, and `unrecognized relative link`.
- The build already emits ~19 pre-existing INFO lines (nav orphans + absolute links). Don't treat them as regressions you caused, and don't mass-fix them unless asked.
- Material prints a "MkDocs 2.0" warning banner on every build. Ignore it; do not upgrade `mkdocs`/`mkdocs-material` on your own.
- Add deps with `uv add "<pkg>"` (updates `pyproject.toml` + `uv.lock`).

Never use bare `mkdocs`/`python -m mkdocs`: there is no global mkdocs, `.venv` has no `pip`, and the required interpreter is 3.13 (`.python-version`) while this machine's `python` is 3.12.

Follow instructions: never write any content unless instructed. Content must be 100% written by the author(s) / human(s).

## Non-obvious structure

- **`nav:` in `mkdocs.yml` is fully manual.** A new `.md` anywhere under `docs/` is invisible on the site until you add it to `nav` (MkDocs only logs an INFO about it). Several files under `docs/projects/` are currently orphans.
- **Exception: blog posts.** `docs/blog/posts/*.md` are picked up by the `blog` plugin; never add them to `nav`. `docs/blog/index.md` is just `# Blog` — the plugin fills it in.
- Post front matter must include `title`, `slug`, `date`, `categories`, `description`, and `comments: true`. Without `comments: true` the giscus block in
  `overrides/partials/comments.html` is skipped (it tests `page.meta.comments`).
- There is no `docs/blog/.authors.yml`, so do not add `authors:` front matter. `docs/blog/.meta.yml` already hides the feedback widget for all posts.
- Blog URLs are `/blog/<year>/<month>/<day>/<slug>/`, and cross-post links are hard-coded absolute site URLs (e.g. `/blog/2026-05-18/git-problems/#...`). Changing a post's `date` or `slug` silently breaks those links.
- Link style: page links use absolute site paths (`/projects/about/`); images/videos use relative file paths (`![...](../../images/x.png)`). Assets are flat in `docs/images/` and `docs/videos/` — no per-post asset folders.
- Several paths contain spaces (`docs/projects/Golf Tracker/database design.md`, `docs/projects/AI Server/...`); quote them in shell commands.

## Math

KaTeX (`docs/javascripts/katex.js`) handles `$…$` and `$$…$$`; MathJax via `pymdownx.arithmatex generic: true` handles `\(…\)` and `\[…\]` — and both engines register `\(…\)`. Prefer `$` / `$$` for new math.

## Deploy and repo conventions

- Pushing to `main` deploys automatically. Commit directly to `main` (no PR flow).
- `gh-pages` is generated by CI (`mkdocs gh-deploy --force`); never edit it. `site/` is gitignored.
- CI installs `mkdocs-material` with **pip**, ignoring `pyproject.toml`/`uv.lock`. Dependency changes land in the local env but not necessarily in the deployed build.
- No `.gitattributes` and `core.autocrlf=true` here, so expect "LF will be replaced by CRLF" warnings; do not mass-normalize line endings in content files. (The `* text=auto` line at the bottom of `.gitignore` is a misplaced, ineffective `.gitattributes` directive.)
- Root `test.py` is gitignored (template rule at `.gitignore:222`); it is scratch code, not part of the site or any test suite.
